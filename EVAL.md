# EVAL.md: Pre-registered Evaluation Plan

Version 0.2, 2026-11-11 (revised after external review: Gate 0 added, label window, deferrals marked; baselines renamed R0 to R8).
**Freeze rule.** Before any model is trained, tag the repository `eval-v1`. Sections 2 to 6 (hypotheses, labels, splits, metrics, success criteria) are then frozen. Any later change creates `eval-v2` and a `DECISIONS.md` entry explaining why and what was already seen. Results are reported for the frozen plan even if they are negative.

All numbers in reports must be produced by scripts that write to `results/`. No result in this file exists yet; every "TBD" must stay "TBD" until a script fills it.

## 1. Hypotheses

| ID | Hypothesis | Evaluated in |
|---|---|---|
| H0 (GATE) | Before any system is built: at pre-command stages (S1 to S3), a learned model predicts future session value better than the best simple rule at matched escalation budgets | Experiment 0 (`EXPERIMENT0.md`) |
| H1 | At matched escalation budgets, the gatekeeper retains substantially more valuable sessions than random or heuristic escalation, so yield per rupee rises versus fixed-tier baselines | Offline (5.1, 5.2), lab, live trial |
| H2 | Serving predicted-low-value visitors from the cheap tier (T1) costs less and loses little yield compared with serving everyone from the hardened tier (T2) | Live trial; natural experiment in the public data (5.3) |
| H3 (DEFERRED, exploratory) | The agent detector generalizes to LLMs not seen in training | Lab, public agent logs (5.4) |
| H4 | The hardened persona scores lower on an independent third-party honeypot detector than the default persona; some detectability remains in every tier | Lab (5.5) |

Negative or null outcomes for any hypothesis are reported with the same prominence as positive ones.

## 2. Labels (frozen)

### 2.1 Value label (Model V)
`value = 1` if the session has at least one of: (a) at least 5 distinct commands; (b) at least one file download or upload; (c) at least one direct-tcpip request. Else 0.
- **Label window.** For a decision at stage k, exclude from that stage's evaluation any session whose prefix up to stage k already satisfies the label; sessions that never reach stage k are excluded and the reach rate is reported (details in `EXPERIMENT0.md`).
- Parameter N_CMD = 5 is frozen as the primary. Report sensitivity for N_CMD in {3, 5, 10}.
- Computable from the dataset's `session_aggregation` fields: `cnt_command_input` (note: count of input events, not distinct commands; distinct counts require event-level data, so use the event-level subset for the primary definition and the aggregate approximation `cnt_command_input >= 5` for the full-scale analysis, and report both), `cnt_file_download`, `cnt_file_upload`, `cnt_direct_tcpip_request` [V, DATA D1].
- **Label dependence on persona.** A session served by a persona that the visitor detected cannot reveal deep behavior. Mitigation: train primarily on sessions from the hardened and persistence configurations; test transfer baseline to hardened (5.3).

### 2.2 Agent label (Model A)
Defined by construction: a session is "agent" iff it was generated by an LLM agent we ran (our own harness runs) or by an LLM agent in the public agent dataset. "Human" iff generated by a consenting volunteer. "Bot" iff it is a replayed or live-collected automated session. No heuristic labeling of wild sessions as agents or humans, because wild ground truth does not exist (the Beyond Bots dataset explicitly has no ground-truth labels [V, DATA D3]).

## 3. Splits (frozen)

- **Temporal split** on the 50-day public dataset: train days 1 to 35, validation days 36 to 42, test days 43 to 50. (Adjust only before `eval-v1`.)
- **Group constraint:** all sessions from the same source IP (as anonymized in the dataset) go to the same fold. Where feasible also group by campaign proxy = (hassh, first-command hash).
- **Honeypot instance:** no instance-level leakage; report a leave-honeypots-out check on a random 20% of the 160 instances.
- Agent detector: leave-one-model-out and leave-one-prompt-out over the public agent dataset (folder structure encodes model and prompt [V, DATA D2]); cross-source tests per SPEC 7.2.
- Random seeds fixed and logged; every split is saved as an artifact.

## 4. Metrics (frozen)

### 4.1 Model V
- Primary: **PR-AUC** (class imbalance). Secondary: precision and recall at fixed escalation budgets; calibration error (ECE).
- **Escalation-efficiency curve (EEC):** x = fraction of all sessions escalated, y = fraction of `value = 1` sessions captured. Headline numbers: recall at 5%, 10%, 20% escalation, with 95% CIs.
- **Early-decision curve:** the same metrics as a function of stage S1, S2, S3, S4, S5.
- Never report accuracy as a headline metric.

### 4.2 Model A
- Recall at fixed false-positive rates of 1% and 5% (on non-agent sessions), with 95% CIs.
- Per-model recall under leave-one-model-out; per-prompt recall under leave-one-prompt-out.
- Cross-source performance (train public, test ours; train ours, test public).
- Humans are few; report **counts** of volunteer sessions flagged, not rates.

### 4.3 System-level
- Yield per session (SPEC 9.1) and cost per session (SPEC 9.2) per arm; **yield per rupee** with the ratio computed per resampling draw, not as a ratio of means only.
- High-value retention at a given escalation budget.
- Escalation rate; false-escalation cost (cost spent on `value = 0` sessions).

## 5. Experiments

### 5.1 Offline study (public data, full scale)
1. Compute base rates of `value` per config and per day. Publish them first (before modelling).
2. Train Model V variants (logistic, gradient-boosted trees, small GRU) on features available at each stage.
3. Produce EEC and early-decision curves on the test period.
3b. **Experiment 0 runs first and gates the rest** (`EXPERIMENT0.md`): learned models versus pre-declared simple rules at each stage. The write-up of 5.1 must lead with that result, including if it is negative.
4. Baselines for escalation (names follow `EXPERIMENT0.md` section 7): **R0** random escalation at the same budget (formerly B1); the simple-rule set **R1 to R7** defined there, which includes the timing-heuristic rule in the style of public bot-vs-human scorers (R4, seconds from login success to first command; style per CLAIMS P11 [S]) (formerly B2); and **R8**, an extra later-stage baseline that is not part of Experiment 0: a lightly re-implemented random-forest profiler in the style of a published adaptive Cowrie system [S, CLAIMS P1] (the paper's code availability is unknown **[U]**, so label it a re-implementation of the idea, not of their system).
5. Ablations: feature groups (handshake only; handshake + auth; + first command; + timing), with and without HASSH, with and without hashed credentials.

### 5.2 Early-decision feasibility
Report, for each stage, the share of sessions that even reach that stage (many sessions end earlier). Decisions at later stages cannot help sessions that never get there.

### 5.3 Natural experiment: persona effect in public data
The 160-instance dataset ran four configurations in parallel (default baseline, hardened, two persistence variants) [V, DATA D1]. Compare session outcomes across configurations (share reaching `value = 1`, session duration, commands per session). Caveats to state: assignment of configurations to instances and regions may be confounded (the dataset's data descriptor must be read to see how instances were assigned **[U]**); adjust or stratify by region/ASN where possible; report results as **associations only, with no causal language**, even if assignment looks random (scanners may target IP ranges, which can confound configuration with attacker population). Causal statements are reserved for the live trial (5.6).

### 5.4 Agent detector study (DEFERRED: exploratory side module)
1. Public agent logs (nine open-weight models, six prompts, five environments, about 16,200 sessions [V/S, DATA D2]). Leave-one-model-out and leave-one-prompt-out.
2. Our own agent runs against the lab sensor (ARACNE and PentestGPT with at least 4 open-weight models via Ollama). Same logging format as negatives.
3. Cross-source tests (SPEC 7.2). A large train-public/test-ours drop is a finding, report it.
4. Stretch: model-family identification. A 2026 study reported that behavioral differences between environments were much smaller than differences between models, enabling cross-environment model identification [S, CLAIMS P4]. Only attempt after the primary study.

### 5.5 Lab adversaries (independent) (PARTLY DEFERRED)
**Status (v0.2):** the third-party detector run and the replay run are MVP-eligible (lab only). The LLM-agent runs and the human blind test are **DEFERRED**, gated by Gate 0 and MVP completion; if not done they are reported as future work, never simulated.

Run on the **lab copy** of the sensor, never on the public sensor.
- **Third-party detector:** honeypot-auditor deep mode against T1, T2 and T3 lab instances. Record its category outcomes and overall score for each tier. Read the installed version's scoring rules and record them (weights have differed across versions in its listings [S]). Use only against our own targets, with its authorization flag [S].
- **Replay:** real botnet command traces from the public dataset, held out from any tuning.
- **LLM agents:** as in 5.4.
- **Human blind test:** at least 20 volunteers. Each gets three unlabeled SSH targets in random order: a real Ubuntu VM, T1, T2. Fixed time box per target (for example 15 minutes). Record "real or honeypot", confidence, and the evidence they used. Report detection rates with Wilson 95% intervals per target. Volunteers are students, not real attackers; state this. Obtain consent; collect no personal data beyond an anonymous id; confirm with faculty whether ethics approval is needed **[U]**.

### 5.6 Live randomized trial (public VPS) (DEFERRED)
**Status (v0.2):** DEFERRED. Gated by Gate 0 passing, SPIKES S1 success and the completed SAFETY pre-launch checklist. Arms A and B in shadow mode come first; adaptive arm C and T3 are future work unless the MVP finishes early.

- **Arms:** A = T1 for all (default baseline); B = T2 for all (hardened baseline); C = full adaptive system. (T3 participates only in arm C.)
- **Assignment:** sticky random assignment per visitor: `arm = hash(secret_salt + visitor_id) mod 3`. Log arm and assignment salt version. Visitors keep their arm for the whole trial.
- **Duration:** a fixed number of days chosen **before launch** from pilot traffic and written to `config/arms.yaml`; no early stopping on results.
- **Independence:** observations from one visitor are correlated; use cluster bootstrap by visitor.
- **Primary endpoint (single):** cost-adjusted yield, defined as yield per rupee, arm C versus arm A and arm C versus arm B.
- **Secondary endpoints:** yield per session, share of sessions with `value = 1`, session duration, early-disconnect-after-login rate, escalation rate, T3 utilization.
- **Power:** unknown until pilot traffic is measured **[U]**. If power is too low for the primary comparison, say so in the report and describe the result as exploratory. Do not increase duration after seeing results.
- Lab and volunteer traffic is excluded by `lab_flag`.

## 6. Statistics

- 95% confidence intervals by bootstrap (10,000 resamples), clustered by source IP/visitor for session-level data. Wilson intervals for proportions.
- Paired comparisons by resampling the same visitors across arms where applicable; otherwise two-sample bootstrap.
- One primary endpoint; secondary endpoints with Holm-Bonferroni adjustment; all other analyses labelled exploratory.
- **Yield weight sensitivity:** 1,000 random weight vectors drawn from a flat Dirichlet over the four yield components; report how often arm C beats arm A and arm B (rank stability).
- **Cost sensitivity:** vary the resource price allocation by plus/minus 50% and report whether conclusions change.
- Manual audit: 100 randomly sampled sessions, labeled by two team members independently for (i) value, (ii) ATT&CK tag rule precision; report Cohen's kappa.

## 7. Success criteria (declared in advance; failure is reportable)

- H0 (gate) is decided only by the rule in `EXPERIMENT0.md` section 12.
- H1 (offline) supported only if Experiment 0 returns PASS-ML or PASS-LATE-ONLY **and** the gatekeeper's recall at a 10% escalation budget exceeds both random escalation (about 10%) and the strongest pre-declared simple rule (R1 to R7 of `EXPERIMENT0.md`), with the cluster-bootstrap CI of the difference excluding zero, on the test period. If Experiment 0 returns FAIL, H1 is reported as not supported and the project reports the rule-based cost-yield analysis instead.
- H1 live-supported if, in the live trial, the primary endpoint's cluster-bootstrap 95% CI for arm C minus arm A (and arm C minus arm B) excludes zero in the favorable direction.
- H2 supported if, among visitors the gatekeeper scores low-value, arm A's yield per rupee exceeds arm B's with the CI excluding zero, while yield per session differs by less than a pre-declared margin (set from pilot data and written before launch).
- H3 supported if leave-one-model-out recall at 5% FPR stays above a pre-declared floor for every held-out model (floor set from the first validation run, before looking at test results) and the cross-source tests are reported.
- H4 supported if the third-party detector's overall score for T2 is lower than for T1 in every repeated run, and the residual signals that remain in T2 are listed.
- If a criterion fails, the report says "not supported" and describes what was observed.

## 8. Threats to validity (must appear in the final report)

1. Value label is a proxy for intelligence value.
2. Labels depend on the persona that produced the session (detected personas truncate sessions).
3. Public-data findings may not transfer to our single-VPS sensor (different IP space, region, uptime).
4. Rare classes (humans, LLM agents) are scarce in the wild; wild AI agents are very rare (one prior deployment saw 8 potential agents in about 8.13 million attempts [S, CLAIMS P3]); agent claims are lab-only.
5. Student volunteers are not real attackers.
6. The cost model depends on a single VPS price and allocation method.
7. The third-party detector is one tool by one author; its verdicts are evidence, not ground truth.
8. Cowrie-based systems stay fingerprintable at the transport layer (see SPEC R5); we measure and report it, we do not claim stealth.
9. Open-weight agent models used in the lab may behave differently from frontier models used by real attackers.
10. A single live trial of limited duration has limited power.

## 9. Reproducibility requirements

- One command per experiment (for example `make offline`, `make lab`, `make trial-report`) that regenerates every table and figure into `results/`. (Planned; these targets do not exist yet.)
- `results/` contains: split files, trained model files with hashes, metric JSON, figure sources, the cost model JSON, and a `MANIFEST.json` with git commit, data hashes (DATA.md), library versions, and seeds.
- Every figure/table in the report cites the script that made it.
